# بازبینی سیستم مقصد — ۲۰۲۶/۱۰/۱۷

این بازبینی برای آماده‌کردن قسمت‌های موجود است؛ قدم ۳۶ یا قابلیت تازه‌ای شروع نشده.
این سند شواهد آزمون را نگه می‌دارد؛ وضعیت معتبر توسعه همچنان در `PLAN.md` است.

## محیط و اصلاح‌ها

- محیط اصلی `.venv`: CPython 3.13.16؛ نسخهٔ انتخابی در `.python-version` ثبت شد.
  وابستگی‌ها با `uv pip check` بررسی شدند. محیط اولیهٔ 3.12 برای بازگشت، به
  `.venv-bootstrap` تغییرنام داده شد و وارد Git نمی‌شود.
- روی محیط اولیهٔ 3.12، Chroma گاهی `Nothing found on disk` داد؛ تست هدفمند و
  مجموعهٔ کامل روی 3.13 موفق شدند. علت درونی خطای 3.12 قطعی نیست و منطق برنامه
  برای پنهان‌کردن آن تغییر نکرد.
- Docker Desktop و WSL موجود بودند؛ موتور به‌علت socketهای مانده و فرایندهای قبلی
  بالا نمی‌آمد. فرایندهای Docker متوقف و پوشه‌های فقط حاوی socket در
  `%LOCALAPPDATA%/Docker/run.preserved-*` و
  `%LOCALAPPDATA%/docker-secrets-engine.preserved-*` حفظ شدند. reset یا حذف volume
  انجام نشد. موتور Docker 29.7.2 در دسترس قرار گرفت.
- کانتینر `rasam-mongo` روی MongoDB 8 متعلق به **rasam-v2** است؛ inspect این مالکیت
  را تأیید کرد. کانتینر و دادهٔ آن تغییر نکردند. نام ثابت کانتینرها از Compose
  این پروژه حذف شد؛ اکنون نام‌ها و volumeها با نام پروژه جدا می‌شوند. پورت‌های
  میزبان قابل تنظیم و فقط روی `127.0.0.1` هستند. روی این ماشین MongoDB این پروژه
  پورت `27018` دارد؛ هر دو URI محلی در `.env` با آن هماهنگ شدند.
- Node 24.19.0، uv 0.13.1 و Wrangler قفل‌شدهٔ 4.151.1 آماده شدند؛
  `uv sync --locked` در `gateway` موفق بود. محیط Workers/Pyodide را خود SDK ساخت.
  `.dev.vars` از تنظیم‌های موجود سرویس مدل ساخته شد و وارد Git نمی‌شود.
- برخی دانلودها در pip/npm/Docker/workerd خطای TLS داشتند. بررسی گواهی خاموش نشد.
  برای اجرای Worker، ماسک `OPENSSL_ia32cap` فقط در فرایند آزمایش اعمال شد؛ برای
  دانلود Docker نیز مسیر جایگزین HTTPS با بررسی SHA-256 هر blob امتحان شد.
  علت ریشه‌ای خطای TLS سیستم هنوز قطعی نیست؛ تنظیم سراسری امنیت یا سیستم تغییر نکرد.

## مهارت‌ها

- `strategic-compact` و `verification-loop` در فهرست مهارت‌های همین جلسه کشف شدند؛
  frontmatter، متن تطبیق‌یافته و مرجع اصلی آن‌ها خوانده و بررسی شدند.
- Verification Loop با آزمون واقعی معماری، desktop، gateway، syntax و diff اجرا شد؛
  تست‌های اجرا‌نشده جدا از موفق‌ها ثبت شدند.
- Strategic Compact یک دستورالعمل است، نه برنامهٔ خودکار. حفظ وضعیت، تصمیم‌ها،
  فایل‌ها، وابستگی‌ها، مسائل باز، تست‌ها و ادامهٔ کار با checkpoint در `PLAN.md`
  انجام و خوانایی آن بررسی شد؛ اجرای خودکار `/compact` ادعا نمی‌شود.
- Codebase Memory محلی `v0.12.1`: شاخص آماده، ۱۷۱۷ گره و ۶۸۳۸ رابطه؛ outline
  فایل تنظیمات و کشف `KnowledgeStore` روی مسیر واقعی پروژه موفق بود. فایل‌های
  تغییرکرده با منبع بررسی شدند؛ گراف جای منبع را نگرفت. watcher خاموش است.

## شواهد فعلی

- مجموعهٔ کامل روی 3.13: **۷۹۸ موفق، ۹۳ skip**، بدون شکست، ۱۳۳ ثانیه؛ پیش از
  آماده‌شدن دیتابیس‌های دمو. این تعداد، وضعیت میانی بازبینی است.
- تست‌های هدفمند Chroma/desktop/gateway روی محیط نهایی: **۹۷ موفق**.
- تست‌های Worker واقعی با دو تست جدید وضعیت و تمدید: **۵ موفق**؛ وضعیت از D1
  واقعی، کلید نامعتبر، انقضا، ابطال، تمدید و مصرف‌نشدن سهمیهٔ status بررسی شدند.
- آزمایش واقعی HTTP رومیزی: نصب نخست بدون لایسنس، فعال‌سازی معتبر، فرادادهٔ هشدار
  شش‌روز، کلید غلط، انقضا و تمدید بدون نصب مجدد؛ کلید در Credential Manager واقعی
  ذخیره شد و دانش مشتری بدون تغییر ماند. لایسنس و راز آزمایشی در پایان حذف شدند.
- تماس زنده با مدل فعلی: پاسخ `OK` با HTTP 200؛ همان تماس از Worker لایسنس‌دار
  هم 200 داد و شمارندهٔ روزانه دقیقاً یک واحد زیاد شد. کلید آزمایش پاک شد.
- API واقعاً روی loopback بالا آمد: `/health` برابر 200، درخواست بدون کلید 401،
  درخواست معتبر با سؤال خالی، خطای فارسی در `Answer` با HTTP 200.
- نحو JavaScript رابط، تنظیم Compose و `git diff --check` موفق‌اند.

## ادامهٔ بررسی

بررسی زیرساخت و قسمت‌های موجود تکمیل شد؛ پذیرش بصری مرورگر و استقرار واقعی
Cloudflare از نتایج HTTP استنتاج نمی‌شوند. قدم ۳۵ برای این بخش‌های باقی‌مانده باز
مانده و قدم تازه‌ای شروع نشده است.

## نتیجهٔ نهایی

- **۸۹۲ تست موفق، صفر شکست، صفر skip، در ۱۱۷٫۶۱ ثانیه** با هر دو دیتابیس و
  Python Worker روشن. گزارش ماشینی: `exports/transfer-pytest.xml` (خارج Git).
- MongoDB **7.0.45** در `rasam-mvp-mongo-1` روی `127.0.0.1:27018` و MySQL
  **8.4.11** در `rasam-mvp-mysql-1` روی `127.0.0.1:3306` آماده‌اند.
  چهار منبع در هر دو: ۱۰۱۶۱، ۱۰۱۴۴، ۲۱۱۲۲ و ۱۰۱۶۹ ردیف؛ کاربر فقط‌خواندنی و
  بررسی آمادگی هر دو مشتری تأیید شد. کانتینر `rasam-v2` حفظ شد.
- دانلود معمول Docker چند بار خطای TLS داد؛ دریافت HTTPS به‌صورت Range و تطبیق
  SHA-256 تمام blobها با manifest رسمی، سپس ورود آرشیو OCI موفق شد. این صرفاً
  روش آماده‌سازی همین سیستم بود؛ ابزار دانلود موقت وارد مخزن نشد.
- سنجهٔ عددی واقعی: **۱۵/۱۵ MongoDB و ۱۵/۱۵ MySQL**؛ برای حفظ سهمیه، گراف سنجه
  خلاصه/نمودار نداشت ولی تولید، گارد، اجرا و ترمیم واقعی بودند. Mongo موارد ۱ تا ۱۳
  را در اجرای نخست گذراند؛ چاپ نتیجهٔ فارسی مورد ۱۴ در اسکریپت موقت به cp1252 خورد
  و آن اجرا قبل از ذخیرهٔ گزارش قطع شد. موارد ۱۴ و ۱۵ پس از اصلاح UTF-8 جداگانه
  موفق شدند؛ فایل `transfer-golden-demo.json` فقط همین دو مورد آخر را دارد.
  `transfer-golden-demo-mysql.json` هر ۱۵ نتیجهٔ MySQL را دارد. هیچ موفقیت
  اجرا‌نشده‌ای به سنجه افزوده نشده است.
- CLI میانگین دما **28.60765672670013** داد؛ CSV با BOM بازخوانی و مقدارش بررسی شد.
  CLI MySQL میانگین توان راکتیو **-27.3142** داد؛ Excel بازخوانی و نوع عددی سلول
  تأیید شد. API نمودار چهارردیفی، خلاصهٔ فارسی و مشخصات نمودار معتبر داد.
- پرسش واقعی از **HTTP رومیزی → Credential Manager → Worker/D1 → مدل واقعی →
  گارد → MongoDB** مقدار صحیح دما و خلاصهٔ فارسی داد. کلید و لایسنس موقت حذف شدند.
  خروجی‌های نمونه در `exports/transfer-*` هستند و وارد Git نمی‌شوند.
- دو مهارت واقعاً در همین جلسه کشف شدند و مطابق دستورشان به کار رفتند؛ اتصال MCP
  محلی از stdio/CLI تأیید است ولی namespace مستقیم آن در این چت قدیمی موجود نیست؛
  یک جلسهٔ تازه برای بارگذاری اتصال تازه لازم است.
- گراف پس از تغییر تست‌ها تازه شد: **۱۷۱۹ گره و ۶۸۴۹ رابطه**؛ فایل‌های راز و
  محیط‌های مجازی خارج شاخص ماندند. همان قالب YAML همچنان تحلیل جزئی دارد.
- پاک‌سازی آرشیوهای دانلود در `%TEMP%/rasam-docker-images` توسط بررسی خودکار
  مجوز با پیام `blocked by policy` رد شد؛ فایل‌های موقت حفظ شدند. محیط‌های
  `.venv-bootstrap` و `.venv313` نیز محلی و خارج Git هستند.

## اجرای دوباره

از ریشهٔ پروژه، برای همین محیط آماده‌شده:

```powershell
$env:Path = "$PWD\.venv\Scripts;$env:Path"
$env:NO_PROXY = "127.0.0.1,localhost,::1"
docker compose up -d
# در ترمینال جدا از پوشهٔ gateway: uv run pywrangler dev --ip 127.0.0.1 --port 8787
$env:RASAM_GATEWAY_TEST_URL = "http://127.0.0.1:8787"
.\.venv\Scripts\python.exe -m pytest -q --tb=short
.\.venv\Scripts\python.exe ask.py "میانگین دمای داخلی اینورترها چقدر است؟"
```

انتظار تست فعلی: `892 passed`؛ میانگین: `28.60765672670013`.
اگر Worker را اجرا نکنید، متغیر `RASAM_GATEWAY_TEST_URL` را تعیین نکنید؛ پنج تست
آن صریحاً skip می‌شوند و این حالت تأیید Worker نیست. اگر Docker پس از خروج با
socket مانده بالا نیامد، ابتدا لاگ همان اجرا را بررسی کنید؛ مشکل سیستم را با
reset یا حذف volume پنهان نکنید. ممکن است برای علت ریشه‌ای TLS بررسی جداگانهٔ
سیستم/شبکه لازم باشد؛ تنظیم دائمی ناامن اضافه نشده است.

نسخه‌های مهم این بررسی: Chroma 1.5.9، pandas 3.0.6، pymongo 4.19.0، pymysql 1.2.3،
sqlglot 30.23.0، langgraph 1.2.16، FastAPI 0.143.3 و pytest 9.1.1.
