# بازبینی تحویل رومیزی — بخش خودکار قدم ۳۸

تاریخ: ۲۰۲۶/۱۰/۱۸. نسخهٔ نصب‌شده `0.1.1`، سرویس عمومی Cloudflare و دیتابیس‌های دمو واقعی.
کاربر اجرای خودکار با حساب‌های آزمایشی را خواست. این گزارش، آزمون خودکار همین میزبان
را ثبت می‌کند؛ پذیرش Windows 10/11 تازه و تمرین فرد غیرفنی در محیط مشتری باز است.

## نتیجهٔ خودکار

- اجرای کامل: **۹۲۶ موفق، صفر شکست، صفر skip** در ۲۰۰٫۲۷ ثانیه؛
  `exports/step38-pytest.xml`. شامل MongoDB، MySQL، D1 و Python Worker محلی واقعی.
- ۱۹۵ تست مرتبط سنجه و معماری موفق. اجرای خود CLI نیز با پاسخ خطای سرویس از یک
  HTTP آزمایشی، exit code برابر ۱ داد و کلید آزمایشی را در خروجی ننوشت.
- بررسی آمادگی `demo` و `demo-mysql` هر دو موفق: اتصال فقط‌خواندنی، چهار منبع،
  سقف ۱۰۰۰ رکورد، دانش کامل، ۹ نمونهٔ معتبر و ۱۵ سؤال طلایی.
- برای هر دیتابیس کاربر تازهٔ فقط‌خواندنی و پوشهٔ دادهٔ خالی جدا ساخته شد.
  فایل نصب‌شده با PATH بدون Python اجرا شد؛ فعال‌سازی واقعی لایسنس، HTTP فرم اتصال،
  انتخاب منابع، ساخت پروفایل، ذخیرهٔ آموزش و پرسش از Worker عمومی انجام شدند.
  پروفایل با خود برنامه ساخته شد؛ فایل دانش از مسیر فرم آموزش ذخیره شد.
- مونگو: پرسش میانگین دما مقدار `28.60765672670013` داد. MySQL: پرسش میانگین توان
  راکتیو مقدار حدود `-27.3142` داد. خواندن عدد واقعی با حساب‌های تازه جداگانه نیز
  پس از گارد سنجیده شد. در پوشه‌های آزمون، رمز و کلید خام لایسنس پیدا نشد.
- حساب‌های ساخته‌شده، رازهای موقت Windows و ردیف‌های لایسنس D1 پاک شدند؛ دادهٔ
  دمو حذف یا seed نشد. شواهد محلی: `exports/step38-wizard-results.json`.
  پاک‌سازی هر پنج حساب ساخته‌شده در تلاش‌های آزمون نیز با خواندن دوبارهٔ مجوزها
  تأیید شد. نصب موقت و میان‌برهای آزمایش پس از پایان، با کنترل مسیر ثبت‌شده حذف
  شدند؛ فایل نصبی نهایی و شواهد در `exports/` باقی‌اند.

## سنجهٔ مدل واقعی از HTTP

| مسیر | نتیجهٔ نهاییِ سؤال‌های یکتا | دامنه |
|---|---|---|
| API واقعی | **۱۵/۱۵ درست** | `demo`، MongoDB، گراف کامل و خلاصه |
| فایل نصب‌شده ← Worker عمومی ← مدل | **۱۵/۱۵ درست** | همان `demo` و داده، گراف کامل |

این نتیجه حاصل چند اجرای ثبت‌شده است. در اجرای اول، سؤال ۷ API خطای دسترسی سرویس
داد و یک تکرار محدود موفق شد؛ بعد محدودیت درخواست در آخر سنجه رخ داد. API تا ۱۴ سؤال
و رومیزی تا ۱۳ سؤال صحیح پیش رفتند. کاربر کلید را در `.env` عوض کرد؛ نام مدل و
ارائه‌دهنده ثابت بودند. پس از پاسخ موفق API، تنظیم Worker با secrets امن هماهنگ شد
و فقط سؤال‌های باقی‌مانده تکرار شدند؛ همه درست پاسخ گرفتند. سناریوی حساب تازه نیز
پس از همین تغییر روی هر دو دیتابیس پاسخ درست گرفت.

خطاهای اولیه حذف نشده‌اند و هرگز پاس شمرده نشدند. گزارش نهایی ادغام بر اساس **متن
سؤال یکتا** است؛ سؤال دوباره‌شده امتیاز اضافه نمی‌گیرد:

- `exports/step38-live-results.json` و `exports/step38-api-resume.json`: اجراهای اولیه.
- `exports/step38-api-after-refresh.json` و `exports/step38-desktop-after-refresh.json`:
  موارد باقی‌مانده پس از اصلاح اتصال توسط کاربر.
- `exports/step38-acceptance-summary.json`: نتیجهٔ نهایی یکتا برای هر مسیر.

کلید مدل داخل نصب‌کننده نیست؛ تغییر کلید، نصب دوبارهٔ مشتری لازم نداشت.
محدودیت ارائه‌دهندهٔ مدل از سهمیهٔ لایسنس جداست؛
[راهنمای OpenRouter](https://openrouter.ai/pricing) و [پشتیبانی](support-playbook.md).

## اصلاح‌های این قدم

`scripts/evaluate.py` دو مسیر `--api-url` و `--desktop-home` دارد. هر دو همان نمره‌دهی
عدد/پیام/نتیجهٔ خالی را استفاده می‌کنند. کلید API از محیط می‌آید و توکن رومیزی از
نشست معتبر loopback خوانده می‌شود. خطای سرویس ارزیابی را ناقص و ناموفق می‌کند و
درخواست‌های بعدی را متوقف می‌کند؛ قبلاً اجرای کاملاً سنجیده‌نشده می‌توانست exit 0 بدهد.

راهنمای کوتاه [کاربر](desktop-quickstart.md) و راهنمای [پشتیبانی](support-playbook.md)
شامل نقش‌های فقط‌خواندنی، ارتباط شبکه، لایسنس، حفظ داده در ارتقا/حذف و ثبت تمرین آماده‌اند.
README و CLAUDE با وضعیت واقعی هماهنگ شدند. اجرای دوم و ارتقای واقعی نصب‌کننده در
[گزارش قدم‌های ۳۶ و ۳۷](windows-installer-review.md) ثبت است.

## مرز پذیرش باقی‌مانده

آزمون همین میزبان، پذیرش ویندوز تازه یا کاربر مستقل نیست. موارد باز برای تحویل نهایی:
Windows 10/11 تازه، تصویر واقعی SmartScreen، دیتابیس شبکهٔ داخلی/اینترنتی مشتری،
تمرین انسانی و ثبت نقاط کمک‌خواستن. پیوند دانلود عمومی فایل نصبی نیز هنوز منتشر
نشده؛ `DOWNLOAD_URL` خالی است. پایان فاز ۶ تا تعیین تکلیف این موارد ادعا نمی‌شود.
