# بازبینی ویندوز پس از دریافت تغییرات مک — ۲۰۲۶/۱۰/۱۹

درخواست کاربر: بارگذاری نسخهٔ جدید و بررسی اشکال، بدون مصرف سهمیهٔ API مدل.
منبع بررسی `c1b01d5` روی ویندوز است؛ تغییرات مک پیش از این بازبینی fast-forward شدند.

## نتیجه

| بررسی | نتیجهٔ واقعی |
|---|---|
| pytest، کل مجموعهٔ جمع‌آوری‌شده | ۱۰۰۷ موفق، ۱۰۳ skip، صفر شکست/خطا، ۱۸۸٫۶۵ ثانیه |
| آزمون‌های سایت با `node --test website/worker.test.mjs` | ۱۰ موفق، بدون شکست/skip |
| فعال‌سازی آزمایشی و ساخت حساب محلی | PASS در مرورگر؛ لایسنس ساختگی، فایل حساب موقت |
| رمز تکراری ناسازگار و ورود با رمز نادرست | PASS؛ پیام فارسی و جلوگیری از ورود |
| خروج و ورود دوباره | PASS؛ محیط گفتگو پس از خروج بسته و پس از ورود باز شد |
| گفتگو، ادامهٔ گفتگو و تفکیک سابقه | PASS با پاسخ ساختگی؛ تعداد پاسخ پیشین ۰ و سپس ۱ |
| گفتگوی مستقل، جستجو و بازگشت/بارگذاری دوبارهٔ تاریخچه | PASS؛ دادهٔ محلی باقی ماند |
| نمایش جدول و نمودار | PASS با دو ردیف ساختگی |
| CSV و Excel از دکمه‌های مرورگر | PASS؛ فایل‌ها دریافت و محتوای آن‌ها با دادهٔ ساختگی تطبیق داده شد |
| فرم اتصال MongoDB و MySQL/MariaDB | PASS برای نمایش و تعویض فرم؛ اتصال واقعی آزموده نشد |
| خطای JavaScript در تب برنامه | مشاهده نشد |
| تماس واقعی مدل | صفر؛ کیفیت مدل و پاسخ روی دیتابیس واقعی آزموده نشد |

## تضمین عدم مصرف سهمیه در این اجرا

فقط برای فرایند بازبینی و فرزندان Python آن، یک audit hook در
`exports/offline-review/sitecustomize.py` اتصال socket به مقصد غیر loopback را پیش
از اتصال متوقف کرد. یک اتصال عمدی به نشانی رزروشدهٔ آزمون رد شد و در گزارش ثبت شد؛
تلاش خارجی دیگری ثبت نشد. نشانی، نام مدل و کلید محیط تست نیز مقادیر ساختگی داشتند.
این حفاظ، تنظیم امنیتی عمومی دستگاه یا کد تولید محصول را تغییر نداد.

رابط واقعی `create_app` با `answerer` و مدیر لایسنس ساختگی در فرایند جدا اجرا شد.
پاسخ‌ها صریحاً «ساختگی برای بررسی رابط» هستند. حساب، گفتگو و پروفایل آزمایش فقط در
`exports/offline-review/data/` هستند؛ هیچ کلید مدل، لایسنس شخصی یا رمز اتصال از vault
برای این رابط خوانده نشد. API حساب و ذخیرهٔ گفتگو واقعی‌اند؛ آزمون پذیرش سرویس مدل
یا مجوز لایسنس واقعی از این نتایج استنتاج نمی‌شود.

## موارد اجرا‌نشده و محیط

۹۳ skip وابسته به MongoDB/MySQL محلی، ۵ مربوط به Worker محلی و ۵ مربوط به امکانات
مخصوص مک بودند. Docker Engine در شروع در دسترس نبود؛ `docker desktop start` تلاش شد
ولی pipe موتور آماده نشد و Desktop خطای راه‌اندازی ثبت کرد. هیچ volume، داده،
تنظیم WSL یا فایروالی حذف/تغییر/بازنشانی نشد. محیط Docker باید جداگانه آماده شود تا
آن ۹۳ آزمون دوباره اجرا شوند؛ skip موفقیت محسوب نشده است.

این بازبینی اجرای کد جدید در ویندوز است، نه بازسازی/نصب نسخهٔ جدید اجرایی یا پذیرش
macOS. نسخهٔ نصب‌شدهٔ کاربر و Workerهای عمومی تغییر نکردند. طراحی سازمانی همچنان
طبق پلن متوقف است و قابلیت تازه‌ای در این نوبت ساخته نشد.

شواهد محلی نادیده‌گرفته‌شده: `exports/offline-review/pytest.log`، `pytest.xml`،
`website-tests.log`، `summary.json`، گزارش حفاظ و `interface.png`.
پیش‌نمایش روی loopback در درگاه ۸۷۹۴ برای مشاهده باز مانده است؛ پرسش‌های آن به مدل
ارسال نمی‌شوند. برای بستن همان فرایند از «خروج از رصام» در پیش‌نمایش استفاده کنید.

## تشخیص تفاوت نصب موجود با منبع — ۲۰۲۶/۱۰/۱۹

پس از پرسش کاربر دربارهٔ قدیمی‌بودن برنامهٔ نصب‌شده، فایل محلی
`%LOCALAPPDATA%/Programs/Rasam/Rasam.exe` بدون اجرا بررسی شد: مقدار نسخه از
ماژول بسته‌شدهٔ `rasam` برابر **0.1.1** و زمان فایل ۲۰۲۶/۱۰/۱۷ بود. صفحهٔ بسته‌شده
فرم حساب محلی و نوار تاریخچه ندارد و با فایل منبع Git یکسان نیست؛ هر دو در منبع
فعلی موجودند و برچسب نسخهٔ منبع 0.1.2 است. پس تغییرات مشترک مک به کد ویندوز رسیده،
اما نصب قدیمی بازسازی/ارتقا نشده است. تب ۸۷۹۴ پیش‌نمایش آزمایشی منبع جدید است.
در این تشخیص نه برنامهٔ نصب‌شده اجرا شد، نه مدل فراخوانی شد و نه نصب تغییر کرد؛
ساخت و نصب خروجی تازهٔ ویندوز برای انتقال قابلیت‌ها به میان‌بر قدیمی لازم است.
