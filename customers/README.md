# مشتری‌ها

هر پوشه اینجا یک مشتری است. **هیچ کدی اینجا نیست** — فقط تنظیمات و دانش دامنه.
برنامه با `RASAM_CUSTOMER=<نام پوشه>` در `.env` می‌فهمد کدام را بخواند.

## فایل‌های یک پوشه‌ی مشتری

| فایل | اجباری؟ | چیست |
|---|---|---|
| `profile.yaml` | بله | نوع دیتابیس، نام متغیر محیطیِ اتصال، کالکشن‌ها/جدول‌های مجاز، قابلیت‌ها، سقف‌ها |
| `documentation.md` | نه | واژگان فارسی ← نام فیلد، توضیح کالکشن‌ها، تله‌های داده. مستقیم وارد پرامپت می‌شود |
| `examples.yaml` | نه | نمونه‌های «سوال ← کوئری» با کلیدهای `question`، `why`، `source` (کالکشن یا جدول) و `query`. هر نمونه باید از گارد رد شود |
| `field_notes.yaml` | نه | یک یادداشت کوتاه کنار خط فیلدهایی که مدل درباره‌شان اشتباه می‌کند |
| `golden_questions.yaml` | نه | سوال‌های طلایی و جواب درستشان از داده‌ی همین مشتری، برای `scripts/evaluate.py` |

## `profile.yaml`

```yaml
db_type: mongodb              # هم‌نام یکی از پوشه‌های rasam/databases/
connection_env: MONGO_URI     # فقط **نام** متغیر؛ مقدارش RASAM_MONGO_URI در .env است
database: solar_telemetry     # نام دیتابیس (راز نیست، پس اینجاست نه در .env)
allowed_sources:          # فهرست سفید؛ هرچه اینجا نیست نه توصیف می‌شود نه خوانده
  - inverter_data
capabilities:                 # قابلیتی که اینجا نیست، اصلاً ساخته نمی‌شود
  - summary                   # خلاصه‌ی فارسی نتیجه (یک تماس اضافه با مدل)
  - repair                    # یک شانس دوم برای کوئری ردشده یا ناموفق
  - chart                     # مشخصات نمودار، فقط وقتی کاربر نمودار بخواهد
  - export_csv
  - export_excel
limits:
  max_rows: 1000
  max_attempts: 2
```

**رمز و connection string هرگز در این پوشه نوشته نمی‌شود.** بارگذار هر مقداری را
که شبیه رشته‌ی اتصال (`mongodb://`، `postgresql://`، …) یا `password=…` باشد رد می‌کند،
و `connection_env` باید فقط یک نام باشد (حروف بزرگ، عدد و `_`).

**پروفایل سخت‌گیر است:** فیلد یا قابلیت ناشناخته، و کلید ناشناخته‌ی `limits`
(مثلاً `max_row` غلط‌املایی) خطای فارسی می‌دهند و بی‌صدا نادیده گرفته نمی‌شوند.
مراحل `prepare`، `generate`، `validate` و `execute` هسته‌اند، نه قابلیت: همیشه
اجرا می‌شوند و نوشتنشان در پروفایل خطاست — گارد هرگز یک گزینه نیست.

برای دیدن گره‌هایی که یک مشتری دارد:

```bash
RASAM_CUSTOMER=demo python ask.py --nodes
```

## افزودن مشتری تازه

ساده‌ترین راه، ابزار تحویل است:

```bash
python onboard.py new
```

اول نوع دیتابیس را می‌پرسد (فقط از آداپتورهای موجود)، **نام** متغیر اتصال را می‌پرسد
(مقدارش را نه می‌پرسد نه چاپ می‌کند و نه می‌نویسد)، منابع دیتابیس را فهرست می‌کند و
شما انتخاب می‌کنید (پیش‌فرض هیچ‌کدام)، و پوشه را از `templates/customer/` می‌چیند.
جاهای خالیِ دانش را با `TODO(onboarding)` علامت می‌زند و حدس نمی‌زند؛ پرکردنشان کار
شماست و با خود مشتری.

مراحل دستی، اگر ابزار را نمی‌خواهید:

۱. پوشه‌ی `customers/<نام>/` و `profile.yaml` بسازید. `db_type` را از فهرست
   پوشه‌های `rasam/databases/` انتخاب کنید.
۲. رشته‌ی اتصال **فقط-خواندنی** را با نامی که در `connection_env` نوشتید در `.env` بگذارید.
۳. `RASAM_CUSTOMER=<نام>` را در `.env` بگذارید و یک سوال بپرسید.
۴. هرجا جواب غلط شد، `documentation.md` و `examples.yaml` را کامل کنید، و
   با `golden_questions.yaml` و `scripts/evaluate.py` بسنجید.
